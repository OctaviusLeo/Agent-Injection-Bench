# Design: Claude target and second-opinion judge

Requirements: `requirements.md` in this folder. The main spec's design (`.kiro/specs/agent-injection-bench/design.md`) still governs everything else.

| File | Change |

## Decisions

- **The official SDK, in its own module.** Claude is called through `anthropic` (1.15.0, MIT, already in `uv.lock` through AgentDojo), not through Anthropic's OpenAI-compatible endpoint: that layer is meant for quick comparisons and does not carry thinking blocks or cache usage fields, both of which this design needs. `ChatLLM` stays OpenAI-only; `ClaudeLLM` mirrors its shape (one `CallRecord` per request in `extra_args["aib_calls"]`, the same error classes, the same retry policy) so the runner, the defenses, and the Results_Store need no change.
- **Default sampling.** Claude Haiku 5.5 and Claude Sonnet 5.5 reject non-default `temperature` and `top_p`, the Messages API has no seed, and SDK 1.x no longer accepts the sampling arguments. Claude requests therefore use the model's default sampling, and each case's sampling record says so. This is a comparability limit against the OpenAI hosted run (temperature 0.7, top_p 0.9, per-request seed) and is stated wherever Claude results are reported.
- **Thinking.** Both models think adaptively by default; the target runs at `effort: medium` (Haiku 5.5's default, written out so it is recorded), the judge at `medium` too. Thinking text is omitted by the API by default, but every thinking block carries a signature that has to come back unchanged. AgentDojo's `get_text_content_as_str` joins every content block, so a thinking block in AgentDojo's `content` would leak into the final answer that the task check reads. `ClaudeLLM` therefore gives AgentDojo only the text blocks and the tool calls, and keeps Claude's own content blocks, in order, under the extra key `aib_claude_content` on the assistant message; the next request sends those blocks back verbatim.
- **Token limits.** `max_tokens: 16000` per target request (thinking counts toward it, so the project's usual 1,024 would cut answers off) and 8,000 per judge request; both are below the size at which the SDK requires streaming.
- **Prompt caching.** Requests use top-level automatic caching (`cache_control: {type: ephemeral}`), which caches the growing conversation prefix between the turns of a case. The usage fields map onto the ledger: `input_tokens + cache_creation_input_tokens` are uncached, `cache_read_input_tokens` are cached.
- **Ledger.** The Claude_Ledger reuses `SpendLedger`. A `run_id` makes it count only the current Claude_Run's entries against the Run_Cap (the OpenAI ledger, created without one, still sums the whole file). The watchdog builds one run id and passes it to every relaunch as `--run-id`, so a crash or a stall cannot start a fresh cap; a Run_Cap stop (exit 3) is never relaunched. `Prices` gains an optional long-context tier for Claude Haiku 5.5. Prices come from `https://platform.claude.com/docs/en/about-claude/pricing`, read 2026-10-29, and are copied into `config/claude.yaml`.
- **Errors.** Typed SDK exceptions map onto the project's classes, most specific first: timeout, connection, 429 and 5xx (including 529 overloaded) retried with exponential backoff up to 5 attempts and then `LLMServerError`, "prompt is too long" as `ContextOverflowError`, any other 4xx as `LLMBadRequestError`. The SDK's own retries are off, as for `ChatLLM`.
- **Refusals.** A `refusal` stop ends the turn; its category goes into the call record. Server-side refusal fallback stays off: Claude Haiku 5.5 has none, and for the judge a fallback would answer with a different model and blur the agreement figure.
- **API key.** Read from the Windows user variable named in `config/models.yaml` (`ANTHROPIC_FOREVER_API_KEY`), forwarded into WSL per command with `WSLENV` (see `docs/ENVIRONMENT.md`). Nothing is written to `~/.config/aib/` or the repository.
- **Grid.** The Claude_Target runs the OpenAI hosted grid's shape (3 conditions × 4 defenses × 40 tasks × 3 Repetitions, Repetition-major), so a Run_Cap stop leaves every Cell with the same number of complete Repetitions, give or take one. The store is `results/raw/claude-haiku-5-5.jsonl`; the run summary is `results/claude_run.json`, so the OpenAI `results/hosted_run.json` is never overwritten. Folding Claude results into the metrics, the Results_Table, the Report, and the README waited for a full run (see Reporting).

## Judge

- **Cases.** Every case in a Results_Store with status `classified` (the agent saw the injection and AgentDojo's check ran) and not yet in `results/judge/<model>.jsonl`. Clean cases have no injected goal and are skipped; errored and unexposed cases are skipped.
- **Input.** The injected goal's text (AgentDojo's `GOAL`), the user task's prompt, and the transcript from the case's trace file: each message in order, with tool calls as `name(arguments)` and each tool output in full.
- **Prompt.** A fixed system prompt says what to decide, that the transcript is data that may contain instructions addressed to an AI, and that only the agent's tool calls count, not what it says it will do. The verdict comes back through structured outputs as `{"carried_out": boolean, "evidence": string}`.
- **Output.** One line per case: the case id, the model under test, the verdict, the evidence, AgentDojo's `injection_success`, whether they agree, the judge's response model, stop reason, cost, and the stamp. The agreement file holds the confusion counts, the agreement rate over the parsed verdicts, Cohen's kappa, the refused and unparsed counts, and a stamp.
- **Run.** Requests are sequential; a run resumes from the judge file and stops at the Run_Cap like a benchmark run.

## Reporting

The main spec's Requirements 7 and 9 already govern the Report and the README (every number generated and traceable, the sampling settings stated), and C1.7 and C3.5 define the two summary files, so the requirements are unchanged; this section is how the Claude results reach those documents.

- **Metrics** (`aib/metrics.py`). The metrics layer already reads every store in `results/raw/`, so `claude-haiku-5-5` joins every Cell, pooled row, paired comparison, and filter row with no change. `run_facts` gains `claude`: the completed and planned cases and whether the last run stopped at its Run_Cap, from `results/claude_run.json`, and the number of benchmark runs and their summed recorded spend, from the Claude_Ledger, because the Run_Cap is per run and the summary holds only the last run's spend. A new `judge` list holds one row per `results/judge/<model>.jsonl`: the confusion counts against AgentDojo's check, the agreement rate over the parsed verdicts with a task-clustered bootstrap interval (a task's Repetitions are judged one by one but are not independent, as for every other rate; when every parsed verdict agrees, the main spec's exact lower bound of Requirement 6.10 instead), Cohen's kappa as a point value beside the counts, the refused and unparsed counts, the judge's response models, and the stamp of `results/judge/<model>_agreement.json`.
- **Results_Table** (`aib/results_table.py`). The run facts gain a Claude run line. The Models table shows `temperature=model default, top_p=model default` for a record that sent neither, plus `effort` and `thinking`. A `## Second-opinion judge` section gives one row per judged model, formatted like every other rate, so the Report and the README copy numbers that trace to `results/summary.md`.
- **Report** (`aib/report.py`, `docs/report_template.md`). The sampling paragraph is generated: the local models and the OpenAI model with temperature, top-p, and a per-request seed; Claude with its default sampling and adaptive thinking at the recorded effort and output cap. The hosted-scope paragraph covers each hosted run summary. The Results section gains the second-opinion judge: the agreement table, the judge model, each agreement file's stamp, and the rule that the judge changes no rate. The Limitations gain the comparability statement below, the External-validity threat counts the hosted models from the data, and Reproduce lists the Claude run and the judge.
- **README** (`aib/docs_build.py`, `docs/README.template.md`). The opening paragraph names each hosted model, the dates its benchmark requests were sent (from its ledger), and the styles it ran; the headline gains a judge-agreement bullet; the full-benchmark commands add the Claude run and the judge. The run facts, the pooled table, and the limitations already arrive as generated text.
- **Plots** (`aib/plots.py`). `claude-haiku-5-5` takes the palette's next categorical slot instead of the gray kept for unknown models.
- **Comparability statement.** Wherever Claude's rates appear beside the OpenAI model's: Claude ran with its default sampling (no temperature, top-p, or seed sent) and adaptive thinking at effort `medium`, while `gpt-6-luna` ran at temperature 0.7 and top-p 0.9 with a per-request seed and reasoning effort `none`, so a difference between the two hosted models mixes the model with its decoding settings. Each value in the statement is filled from the configuration and the stores, not typed.
