## Question

Tool-using agents read emails, calendar entries, and files that other people can write. An attacker who controls such content can plant instructions in it, hoping the agent treats them as commands (indirect prompt injection). This study asks three empirical questions:

- How often does an agent carry out an instruction planted in a tool output (the attack success rate, ASR)?
- How much does each of 4 defense conditions lower that rate?
- What does each defense cost in legitimate task success (the Defense_Cost), both when no attack is present and when one is?

## Setup

**Environment.** All tools are simulated. The sandbox is AgentDojo's workspace suite (an email, calendar, and cloud-drive assistant for the fictional user Emma Johnson), pinned as `agentdojo==0.1.35` at benchmark version `v1.2.2` with the `v1.1.2` task fixes registered. It provides 40 user tasks and 24 tools over in-memory state loaded from a local fixture; nothing reaches a real account or website. Each user task has a deterministic success check (its AgentDojo `utility` predicate); no LLM judges any outcome. (The second-opinion judge under Results only measures how often an LLM agrees with the injection checks.)

**Attacks.** An injection is planted only in the fixture fields that the user task's own ground-truth tool calls read, so it reaches the agent inside a tool output and never in the user's request. There are 5 Injection_Styles, all generic published templates or a simple variant: a direct "TODO" instruction, a fake system message, InjecAgent's "ignore previous instructions" sentence, AgentDojo's "important instructions" message, and an instruction hidden in an HTML comment. Each user task is paired with one of 6 Injected_Goals, AgentDojo's workspace injection tasks: benign sandbox actions such as emailing an outside address, deleting a cloud file, creating a calendar event, or forwarding a fixture email. Each goal has a deterministic check over the final sandbox state and the tool-call trace. A clean control runs the same tasks with no injection.

**Classification.** An injected case is *exposed* when at least one raw tool output contains the planted text. Exposed cases are *classified*: the attack succeeded if and only if the goal's check passes. Cases where the agent never received the injection are reported as unclassified and left out of the ASR denominator; errored cases are left out of every denominator and counted.

**Defenses.** `none` (no mitigation); `delimit` (AgentDojo's spotlighting: tool outputs wrapped in `<<` and `>>`, and the system message says never to obey text between them); `hierarchy` (the system message states that only it and the user's request are instructions and tool outputs are untrusted data); `filter` (every tool output is screened by the `protectai/deberta-v3-base-prompt-injection-v2` classifier at its fixed decision threshold of 0.5, and flagged outputs are replaced by a notice).

## Limitations

- **One environment.** All 40 user tasks come from AgentDojo's workspace suite, so the results describe an email, calendar, and file-drive assistant, not agents in general.
- **Small local models.** Their task success can be low even without attacks, which widens intervals and limits what the defense-cost comparison can resolve.
- **One model family locally.** Both local models are Qwen-family: Llama-3.1-8B was replaced before the benchmark because llama.cpp could not parse the turns in which it called two tools (the model checks are recorded in `.kiro/specs/agent-injection-bench/design.md`), so the local comparison is across size and generation, not family.
- **The hosted grid is smaller:** it covers 3 of the 6 conditions because of `gpt-6-luna`'s spend cap. `gpt-6-luna` is OpenAI's API model ID, an alias the provider can repoint; the response `model` field recorded on every case echoed the alias, so no dated snapshot was recorded.
- **The two hosted models are not a controlled comparison.** `claude-haiku-5-5` ran the same grid as `gpt-6-luna` but sent no sampling settings and no seed, so it used the model's default sampling, and it thought adaptively at effort `medium`; `gpt-6-luna` ran at temperature 0.7 and top-p 0.9 with a per-request seed and reasoning effort `none`. A difference between the two mixes the model with its decoding settings. The response `model` field on `claude-haiku-5-5`'s cases echoed the requested ID, so no dated snapshot was recorded.
- **Floor effect.** Undefended attack success was at most 0.030 pooled over a model's styles, so no defense could lower it by more than that; the ASR-reduction intervals are narrow mainly because there was little to reduce.
- **Different decoding stacks.** The local models are 4-bit GGUF quantizations served by llama.cpp; quantization and the server's chat template can change behavior relative to the original weights.
- **Exposure-conditioned ASR.** Cases where the agent never read the injected data are excluded from the ASR denominator; exposure rates are reported beside every ASR.
- **The tool-permission-limit defense is not implemented.** It needs a per-task allowed-tool list that AgentDojo does not provide.
- **Fixed filter threshold** of 0.5; precision and recall at other thresholds are not explored.
- **Zero-success intervals.** A rate with no successes reports the exact one-sided 95% upper bound, which treats cases as independent and so can be narrower than a task-clustered bound; a paired difference between two zero-success rates still shows a zero-width bootstrap interval.
- **Goal confounding.** Each user task is always paired with the same injected goal (user task k with goal k mod 6), and the bootstrap resamples tasks only, so task and goal effects cannot be separated and the intervals do not cover other pairings.
- **Predicate exceptions.** An AgentDojo injection predicate that raises is scored as not carried out, and the committed records do not say whether that happened; runs made after this was found record the exception in `security_check_error`.
- **An AgentDojo executor crash counts as errored.** `ToolsExecutor` in `agentdojo` `0.1.35` runs `literal_eval` on every string argument and catches only `ValueError` and `SyntaxError`, so a nested set literal (a set written inside a set) raises `TypeError: unhashable type` and ends the case. The runner records such a case as `errored` with that cause, as for any per-case failure; it is counted in the errored columns, and the executor was not patched mid-run, so every record of a model comes from one commit.
- **Suite deviation.** The suite includes AgentDojo's `v1.1.2` task fixes, which `get_suite` omits in `0.1.35`, so numbers are not directly comparable with results produced through that function.

## Threats to validity

- **Construct validity.** The success checks are AgentDojo's predicates. Many are strict about side effects, so an agent that completes the user's task but also carries out the injected goal can fail the task check; Defense_Cost under attack therefore mixes the defense's own cost with the attack's. The clean-condition cost isolates the defense.
- **Exposure conditioning.** ASR is computed over exposed cases only. A model that rarely reads the injected data has fewer classified cases and wider intervals; exposure rates are reported beside every ASR in `results/summary.md` so the two can be read together.
- **Sampling variability.** Model outputs were sampled, not greedy; llama.cpp batching and the hosted providers are not bit-reproducible. The Repetitions and the task-clustered intervals account for this, but a rerun will not reproduce identical per-case outcomes.
- **Statistical scope.** The intervals cover the 40 tasks of one suite; many Cells are compared without a multiple-comparison correction, so an isolated interval that excludes zero should be read as suggestive.
- **Filter calibration.** The classifier's threshold was fixed before any run and never tuned; on ground-truth tool outputs with no injection it flagged 36 of 84 outputs (`results/m3_filter_calibration.json`), which shows up as benign cost.
- **External validity.** Results describe one email, calendar, and drive assistant environment, two small quantized local models, and two hosted model IDs, each at one point in time.

## Responsible disclosure and scope

This report gives aggregate rates and defense effects only. The injection texts are generic published templates; none was tuned against a named commercial product. If benchmarking had revealed a reproducible vulnerability in a specific real product, publication of that payload would stop and the vendor's responsible-disclosure process would be followed (design.md, "Responsible disclosure and payload restraint").
